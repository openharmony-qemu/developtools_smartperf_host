## 2. 数据流架构

### 2.1 零重复解析路径（浏览器已有 trace）

```
用户: "浏览器里已经打开了 trace，帮我分析卡顿"
  │
  ▼
OpenCode LLM → 调用 sp-get-current-trace
  │
  ▼
MCP Server BrowserBridge.requestExportDb()
  │
  ▼ WebSocket cmd=5 (EXPORT_DB)
扩展服务 → 转发到浏览器
  │
  ▼
SpAgentListener.executeExportDb()
  │ threadPool.submit('download-db')
  ▼
WASM trace_streamer._WasmExportDatabase()
  │ 1MB 分片 → 合并 → Uint8Array
  ▼
WebSocketManager.sendMessage(AGENT_TYPE, EXPORT_DB, reqBufferDB)
  │
  ▼ WebSocket
扩展服务 agent.js → 写入磁盘 ({code:0, message: dbPath})
  │
  ▼ WebSocket cmd=100 (RESULT)
MCP Server BrowserBridge → 收到 dbPath
  │
  ▼
TraceEngine.setDbFile(dbPath) → better-sqlite3(readonly)
  │
  ▼
返回 "DB file loaded (XX tables)" → LLM 可继续调用分诊工具
```

### 2.2 本地文件路径（浏览器未打开）

```
用户: "分析 D:/traces/issue.pbreader.htrace"
  │
  ▼
OpenCode LLM → 调用 sp-set-trace-file
  │
  ▼
MCP Server TraceEngine.setTraceFile()
  │
  ▼
execFile(trace_streamer, [traceFile, '-e', dbPath])
  │ 30s ~ 5min (取决于文件大小)
  ▼
better-sqlite3(dbPath, {readonly: true})
  │
  ▼
返回 "Trace file set. DB exported successfully." → LLM 可继续调用分诊工具
```

### 2.3 分诊 → 深度分析 → UI 联动（LLM 自主闭环）

```
LLM: "我来分析卡顿问题"
  │
  ├─→ sp-triage-jank ──→ "发现 3 个进程有 jank, flag=1"
  │                         │
  │                         ▼ LLM 观察结果，决定下一步
  ├─→ sp-analyze-jank-detail(ipid=5) ──→ "帧 42 耗时 83ms"
  │                                        │
  │                                        ▼ LLM 观察结果，决定下一步
  ├─→ sp-jank-cpu-context(ipid=5) ──→ "CPU 被线程 123 抢占"
  │                                    │
  │                                    ▼ LLM 观察结果，决定下一步
  ├─→ sp-focus-range(startTime=X, endTime=Y) ──→ 浏览器自动聚焦
  │
  └─→ 输出诊断报告
```

```

│  │ type │ cmd  │ s_id │      session     │ d_len │reserved ││

│  └──────┴──────┴──────┴──────┴──────┴──────┴──────────┘│
│  字节序: BIG-ENDIAN (DataView.setUint16/setUint32)      │

│  type: 0=系统, 8=诊断, 20=Agent                         │

```

## 7. Agent 架构本质

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│   SP Host Agent = LLM (大脑) + MCP 工具 (手眼)                   │
│                                                                  │
│   ┌──────────────────────────────────────────────────────────┐   │
│   │                   LLM (OpenCode)                         │   │
│   │                                                          │   │
│   │   意图理解 → 规划决策 → 工具调用 → 结果观察 → 下一轮      │   │
│   │                                                          │   │
│   │   ✓ 规划: "先分诊，再深度分析"                            │   │
│   │   ✓ 观察: "flag=1 说明有卡顿"                             │   │
│   │   ✓ 决策: "需要调用 jank-detail"                          │   │
│   │   ✓ 自校正: "SQL 报错，查表结构后重试"                    │   │
│   │   ✓ 反馈闭环: 每步结果回到 LLM 重新决策                   │   │
│   │                                                          │   │
│   └────────────────────────────┬─────────────────────────────┘   │
│                                │                                 │
│                                ▼                                 │
│   ┌──────────────────────────────────────────────────────────┐   │
│   │              MCP Server (工具基础设施)                     │   │
│   │                                                          │   │
│   │   34 个工具 = Agent 的能力边界                             │   │
│   │   TraceEngine = Agent 的记忆 (DB)                        │   │
│   │   BrowserBridge = Agent 的眼 (浏览器) + 手 (UI操作)       │   │
│   │   Skills/Knowledge = Agent 的可扩展知识                    │   │
│   │   Workflows = Agent的预置经验                             │   │
│   │                                                          │   │
│   └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│   LLM 就是 Agent 引擎，MCP 工具就是 Agent 能力                   │
│   我们做的就是提供好工具，不需要额外加 Agent 层                    │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```
